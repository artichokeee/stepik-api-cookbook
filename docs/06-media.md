# 06. Медиа

## Видео в шаге

### Загрузка

`POST /api/videos`, тело `multipart/form-data`:

| Поле | Значение |
|---|---|
| `lesson` | id урока |
| `source` | сам файл |

**Ожидание:** файл передается в поле `file`.
**На деле:** поле называется `source`.
**Что делать:** `source`. И не ставьте `Content-Type` вручную – библиотека сама проставит его вместе с `boundary`.

```python
with open("intro.mp4", "rb") as f:
    r = s.post(f"{API}/videos", data={"lesson": LESSON_ID},
               files={"source": ("intro.mp4", f, "video/mp4")}, timeout=600)
video = r.json()["videos"][0]       # status: "raw", urls: []
```

Вместо файла можно передать публичную ссылку на него в поле `source_url`.

Объект видео: `{id, thumbnail, urls: [{quality: "240" | "360" | "720", url}], duration, status: "raw" | "ready", upload_date, filename}`.

### Шаг с видео

Создайте шаг, передав объект видео **целиком**:

```json
{"stepSource": {"lesson": 1, "position": 1,
                "block": {"name": "video", "text": "", "video": { "id": 123, "status": "raw", "urls": [] }}}}
```

### Ожидание готовности

**Ожидание:** состояние перекодирования можно спросить у `GET /api/videos/<id>`.
**На деле:** этот адрес отвечает 404.
**Что делать:** перечитывайте шаг (`GET /api/step-sources/<id>`) и смотрите `block.video.status` и `block.video.urls`. Ссылки появляются, когда статус становится `ready`; обычно это секунды.

### Пределы (по справке Stepik)

| Способ | Предел |
|---|---|
| загрузка файла | до 100 МБ, до 1920×1080 |
| по ссылке (`source_url`) | до 500 МБ, публичная ссылка |
| `iframe` (Google Drive, VK и т.п.) в текстовом шаге | без предела |

`iframe` переживает санитайзер ([05-step-types.md](05-step-types.md#санитайзер-html)), так что длинное видео можно встроить рамкой в текстовый шаг.

## Видео-превью курса

Проверено в ноябре 2026 на тестовом курсе.

1. Загрузка – тот же `POST /api/videos`, но с полем `course=<id>` вместо `lesson`, плюс `source`. Ответ – `videos[0]` со `status: "raw"`.
2. Привязка – `PUT /api/courses/<id>` с полным объектом курса и `intro_video: {"id": <videoId>}`.

**Ожидание:** достаточно передать число: `intro_video: 665359`.
**На деле:** запрос с голым числом отвечает 200 и молча ничего не меняет.
**Что делать:** только объект `{"id": ...}`. `intro_video: null` снимает превью.

Откат – тот же `PUT` с прежним `{"id": ...}`: при замене старое видео не удаляется.

## Картинки

Встроенный `<svg>` и картинки `data:` санитайзер вырезает, поэтому картинка в шаге – только `<img src="https://...">` с адресом файла в интернете. Редактор Stepik хранит загруженные картинки на Uploadcare.

### Доступность CDN по регионам

**Ожидание:** адрес картинки одинаково открывается у всех учеников.
**На деле:** у хранилища Uploadcare, которым пользуется Stepik, две витрины с одними и теми же файлами:

| Хост | Где | Доступность |
|---|---|---|
| `ucarecdn.com` | Fastly, зарубежный CDN | из России соединение не устанавливается (замер в сентябре 2026: 15 секунд без ответа) |
| `ucarecdn.stepik.net` | витрина, которой пользуется сам редактор Stepik | из России отвечает за доли секунды; доступна не во всех странах |

Файл по обоим адресам один и тот же: 30 адресов (png, svg, jpeg), сверенные побайтово, совпали все.

**Что делать:** в шагах ссылайтесь на `ucarecdn.stepik.net`. Старые ссылки на `ucarecdn.com` можно заменить на `ucarecdn.stepik.net` с тем же путем. Учеников из стран, где эта витрина недоступна, это не спасает – если они для курса важны, держите картинки на своем хостинге.

### SVG

Схему загружайте файлом `.svg` и вставляйте как `<img src>`.

**Ожидание:** если файл по ссылке отдается с кодом 200, картинка покажется.
**На деле:** SVG отдается как `image/svg+xml`, и `<img>` разбирает его **строгим** XML-парсером. Любая ошибка XML – и вместо схемы пустая рамка, хотя сервер по-прежнему отвечает 200. Частая причина – повторенный `xmlns` в корневом `<svg>`: повтор имени атрибута – фатальная ошибка XML.
**Что делать:** перед загрузкой проверяйте файл:

- в корне ровно один `xmlns="http://www.w3.org/2000/svg"`;
- ни одного повторенного атрибута;
- `&` записан как `&amp;`.

Уже загруженный файл проверяется так: `curl -s <адрес> | head -c 200`, а надежнее – любым XML-парсером.
