# 07. Комментарии, уведомления, новости курса

Все ниже – про собственный курс автора: ответить ученику, отметить уведомление, отправить новость тем, кто записан на курс.

## Комментарии

Обсуждение шага – двухуровневое: корневой комментарий и ответы на него. У ответа `parent` – id корневого комментария, у корневого `parent: null`. `target` – id шага.

| Что | Запрос |
|---|---|
| корневые комментарии курса | `GET /api/comments?course=<id>&parent=null` |
| ответы на комментарий | `GET /api/comments?parent=<id>` |
| комментарии по id | `GET /api/comments?ids[]=...` (без `course`) |
| написать | `POST /api/comments` |
| поправить | `PUT /api/comments/<id>` |
| удалить | `DELETE /api/comments/<id>` |

Ответ на комментарий:

```json
POST /api/comments
{"comment": {"target": STEP_ID, "parent": ROOT_COMMENT_ID, "text": "<p>Спасибо, поправил.</p>", "thread": "default"}}
```

**Ожидание:** отвечая на ответ внутри обсуждения, в `parent` ставят id того ответа.
**На деле:** уровней только два.
**Что делать:** `parent` – всегда id корневого комментария.

Правка – `PUT` полным объектом: `target`, `parent`, `text`, `thread` (по умолчанию `"default"`). Прочитайте комментарий, замените `text`, отправьте все четыре поля.

## Уведомления

| Что | Запрос |
|---|---|
| страница уведомлений | `GET /api/notifications?page=1` |
| только непрочитанные | `&is_unread=true` |
| только про комментарии | `&type=comments` |
| отметить одно прочитанным | `PUT /api/notifications/<id>` с `{"notification": {"id": <id>, "is_unread": false}}` |
| отметить все | `POST /api/notifications/mark-as-read` с `{}` |

**Ожидание:** общая лента покажет все, что нужно.
**На деле:** уведомления разных видов идут вперемешку, и нужные тонут среди остальных. Часть уведомлений приходит с `type: "default"`.
**Что делать:** листайте ленту нужного вида (`type=comments`, `type=default`), а не общую.

Найти уведомление о конкретном комментарии можно по ссылке в его `html_text`: там стоит `discussion=<id корневого комментария>` или, для ответа в обсуждении, `reply=<id ответа>`. Ищите оба варианта. Сравнивая числа, следите за границей: `reply=54` не должно совпасть внутри `reply=548`.

## Новости курса (announcements)

Факты ниже выяснены на тестовом курсе один раз. Повторять эксперименты не нужно: защита Stepik закрывает доступ с IP за серию одинаковых отбитых запросов.

### Жизненный цикл

```
POST /api/announcements                {"announcement": {"course": COURSE_ID, "subject": "...", "text": "<p>...</p>"}}
                                       → status: "composing" (черновик)
POST /api/announcements/<id>/send      → включить рассылку
POST /api/announcements/<id>/abort     → остановить
```

- Черновик в `composing` никогда не отправляется сам, поэтому создавать его безопасно.

**Ожидание:** отправка – `/publish` или `/queue`, либо `PUT` со `status`.
**На деле:** `/publish` и `/queue` отвечают 404; `status` и `next_date` только читаются, `PUT`, который их меняет, молча игнорируется.
**Что делать:** включать – `POST .../send`, останавливать – `POST .../abort`.

**Ожидание:** снять у включенного триггера флаги `PUT`-ом – значит его выключить.
**На деле:** включенная рассылка продолжает работать.
**Что делать:** только `abort`.

- `subject` – до 255 символов.
- Stepik подставляет в текст `{{user_name}}`; собственный шаблон редактора начинается с `Здравствуйте, {{user_name}}!`.
- Триггеры курса видны только через `GET /api/announcements?course=<id>`; запрос по `?user=` их не показывает.

### Виды рассылок курса

| Вид | Поля |
|---|---|
| разовая | – |
| по расписанию | `is_scheduled: true`, `start_date`, `mail_quantity: 1` |
| при записи на курс | `on_enroll: true`, `is_infinite: true` |
| при наборе N% баллов | `is_restricted_by_score: true`, `score_percent_min: N`, `score_percent_max: 100`, `is_infinite: true` |

Фильтр "кому" действует только на разовую рассылку и рассылку по расписанию.

### Включенный триггер не редактируется

Проверено в ноябре 2026 на тестовом курсе.

**Ожидание:** текст работающего триггера можно поправить `PUT`-ом.
**На деле:** `PUT` на включенную рассылку → 403. `abort` у рассылки, которая уже что-то отправила, переводит ее в `aborted`, а не в `composing`, и такая рассылка отвечает 403 и на `PUT`, и на `DELETE`.
**Что делать:** новый текст – это новая рассылка: создайте ее, включите `send`, и только потом остановите старую `abort`. В таком порядке нет промежутка, когда не работает ни одна.

### Триггер по баллам срабатывает сразу

**Ожидание:** триггер "при наборе N% баллов" сработает, когда ученик дойдет до N% после включения.
**На деле:** письмо сразу уходит **всем, у кого этот процент уже есть**. Триггер с `score_percent_min: 0` дошел до единственного ученика тестового курса за секунды. Значит, замена работающего триггера по баллам повторно отправит письмо всем, кто получил старое.
**Что делать:** прежде чем заменять триггер по баллам, решите, готовы ли вы к повторной отправке. Триггер "при записи" ведет себя иначе: уже записанным он не пишет (очередь после включения – 0), его замена безопасна.
