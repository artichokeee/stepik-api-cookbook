# 08. Ошибки и ограничения

## Тело ошибки

Валидатор отвечает JSON в одном из видов:

```json
{"title": ["Обязательное поле."]}
{"title": ["Убедитесь, что это значение содержит не более 64 символов (сейчас 89)."]}
{"field": [{"text": "..."}]}
{"detail": "..."}
```

Общие ошибки, не привязанные к полю, лежат под `__all__` или `non_field_errors`. Показывайте человеку и имя поля, и причину: "Stepik 400" без тела разобрать невозможно. Если тело не JSON, покажите его начало как есть.

## Коды

| Код | Значит | Повторять? |
|---|---|---|
| 400 | валидатор отклонил тело: см. текст | нет, исправьте запрос |
| 401 | токен истек или не принят | получите новый токен, потом один повтор |
| 403, тело JSON | нет прав на объект или действие | нет |
| 403, тело HTML | ответ защиты Stepik, а не API | нет, см. ниже |
| 404 | объекта нет или адрес не существует (например, `GET /api/videos/<id>`) | нет |
| 405 | метод не поддерживается (например, `DELETE /api/course-images/<id>`) | нет |
| 429 | слишком часто | да, с паузой |
| 5xx | сбой на стороне Stepik | да, с паузой |

## Повторы с паузой

Повторяйте только 429, 5xx и обрыв связи. Остальные 4xx – ответ про конкретный запрос, повтор вернет то же самое.

| Ситуация | Повторов | Паузы |
|---|---|---|
| 429 или 5xx | до 2 | 1,5 с, затем 6 с, плюс случайные 0–0,5 с |
| обрыв связи или таймаут | до 2 | 1 с, затем 2 с |

- Таймаут на каждую попытку – 30 секунд. Без него зависший запрос держит соединение минутами.
- Случайная добавка к паузе нужна, чтобы параллельные запросы не повторялись одновременно.

```python
for attempt in range(3):
    r = s.request(method, url, timeout=30, **kw)
    if (r.status_code == 429 or r.status_code >= 500) and attempt < 2:
        time.sleep(1.5 * 4 ** attempt + random.random() * 0.5)
        continue
    break
```

## Когда Stepik лежит целиком

**Ожидание:** повторы спасают от временных сбоев.
**На деле:** при общем сбое (октябрь 2026: 502 на все запросы, включая выдачу токена, каждый ответ – около 8 секунд) каждый вызов с повторами стоит около 30 секунд, а страниц и задач, ждущих Stepik, много.
**Что делать:** поставьте предохранитель:

- после 3 сбоев подряд (5xx или обрыв связи) без единого удачного ответа между ними – минуту не ходить в Stepik вовсе;
- через минуту пропустить один пробный запрос, без повторов; ответил – предохранитель снят, нет – еще минута;
- одиночный 500 на конкретный запрос бывает и у живого Stepik, поэтому предохранитель срабатывает только на серию;
- 401, 403 и 404 сбоем не считаются: это ответ про запрос, а не признак падения.

## Как не попасть под блокировку

API стоит за защитой от DDoS (QRATOR). Она смотрит на IP-адрес и закрывает его на 5–10 минут для всех запросов. Блокировка выглядит как 403 с HTML-страницей ("Access Blocked") вместо JSON.

Что к ней приводит:

- **HTML в теле `POST /api/courses`.** Описание курса с разметкой при создании защита принимает за атаку.
- **Серия отбитых запросов подряд**, особенно к одному ресурсу.
- **Всплеск параллельных запросов** с одного адреса.

Как работать, чтобы до нее не доходило:

- Делайте паузу между запросами (около 350 мс) и держите несколько одновременных запросов, а не десятки.
- Если с одного адреса работают несколько процессов или пользователей, пауза после блокировки должна быть общей для всех: пока соседи продолжают обращаться, блокировка не снимается.
- Получили 403 с HTML – остановитесь. Подождите хотя бы минуту, повторите один раз. Снова блокировка – не повторяйте тот же запрос, меняйте подход.
- Эксперименты (подбор схемы шага по жалобам валидатора, проверка пределов полей) – с паузой между попытками и с потолком числа попыток.
- Пишите в Stepik только то, что изменилось, и не перечитывайте одно и то же в цикле.

## Отличить блокировку от отказа в правах

```python
ct = r.headers.get("content-type", "")
if r.status_code == 403 and "json" not in ct:
    raise SystemExit("Блокировка защиты Stepik: остановитесь на несколько минут.")
```

403 с JSON – это API: прав на объект нет, повтор не поможет.
